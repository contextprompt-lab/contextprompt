How task extraction works

A multi-stage pipeline that turns raw conversation into implementation-ready output.

1

Transcript ingestion & chunking

The meeting recording is transcribed with speaker diarization. Long transcripts are automatically split into overlapping chunks so no discussion is lost at a boundary. Utterances from the same speaker within a 2-second window are merged to reduce noise.

Whisper transcription · speaker merging · chunking
2

Repo scan & codebase indexing

contextprompt walks your connected repositories, respecting .gitignore. It parses TypeScript and JavaScript files to extract exported functions, types, interfaces, and file paths — building a map your AI coding assistant can act on. The scan is capped at ~30k tokens per repo to keep extraction fast and focused.

AST parsing · .gitignore-aware · 30k token budget
3

Claude API multi-stage extraction

The transcript and repo map are sent to Claude. Extraction runs in stages: project summary → file name search using bigrams and trigrams from the transcript → keyword scoring against repo symbols → content search for most relevant files → final task generation with full source context. Responses are validated with Zod schemas — if Claude returns invalid JSON, the pipeline retries rather than silently returning empty results.

Claude API · multi-stage · Zod validation · retry on error
4

Deduplication & structured output

Tasks extracted from overlapping chunks are deduplicated using Jaccard word similarity. The final set is saved to your dashboard with titles, file paths, implementation steps, confidence levels, and verbatim transcript evidence. Every task is one click away from your clipboard — ready to paste into Claude Code, Cursor, or a GitHub issue.

Jaccard dedup · structured JSON · one-click copy

What makes the output different

Every field in a contextprompt task is there because AI coding assistants need it.

Real file paths

Tasks reference actual files from your codebase — src/routes/auth.ts, not "the auth module." contextprompt matches discussion topics to your file tree using bigram/trigram search and keyword scoring against exported symbols.

Implementation steps

Each task includes an ordered list of concrete steps. Not "update the auth flow" but "add POST /api/auth/refresh, validate against SQLite, issue new token with 15-minute expiry." Steps are derived from the meeting discussion and cross-referenced with your codebase.

Confidence scores

Every task carries a confidence score from 0.0 to 1.0. Low-confidence tasks are flagged so you can review them before acting. High-confidence tasks can flow directly into AI coding assistants with no human review.

Transcript evidence

Each task links to the exact quote and speaker that prompted it. When you need to verify what was actually decided — or who said what — the evidence is one click away without rewatching the recording.

Validated structured JSON

Output is validated against a strict Zod schema before it reaches your dashboard. Invalid or incomplete responses trigger a retry rather than silently returning partial data. You always get complete, structured tasks or an explicit error.

Chunk-aware deduplication

Long meetings are chunked for extraction. Tasks that appear in multiple chunks are deduplicated using Jaccard word similarity so each coding task appears exactly once, even if it was discussed several times throughout the call.

Frequently asked questions

Everything about how task extraction works in practice.

How accurate is the task extraction?
Accuracy depends on how clearly the meeting discusses implementation details. Tasks that reference specific modules, functions, or files by name consistently score above 0.85. Vague discussions produce lower-confidence tasks that are flagged for your review. In our testing, ~80% of extracted tasks from a typical sprint planning call require no editing before being passed to an AI coding assistant.
What meeting platforms does contextprompt support?
contextprompt supports Zoom, Google Meet, Microsoft Teams, and Slack huddles. You paste a meeting URL into the dashboard and the bot joins as a participant. No browser extensions or local software required. See the AI meeting assistant page for full details.
Which programming languages and repos are supported?
Repo scanning works for any file-based repository. TypeScript and JavaScript files are indexed at the AST level to extract exported functions, types, and interfaces. Other languages are included in the file tree so contextprompt can still reference paths in extracted tasks — just without deep symbol extraction.
How long does extraction take after a meeting ends?
For a 1-hour meeting with a connected repo, tasks typically appear in the dashboard within 2–4 minutes of the meeting ending. The bot processes the recording as it becomes available and runs the extraction pipeline immediately — no manual trigger needed.
Can I edit extracted tasks before sending them to GitHub or Jira?
Yes. Every task in your dashboard can be edited before you export it. You can adjust the title, file paths, steps, or any other field. Pro users can push tasks directly to GitHub Issues, Jira, or Linear with a single click.
What happens if the meeting is very long?
Transcripts longer than ~100k tokens are automatically split into overlapping chunks for extraction. Each chunk is processed independently and tasks are merged using Jaccard similarity deduplication — so if a topic was discussed in both the first and second half of a 3-hour meeting, you get one task, not two.
